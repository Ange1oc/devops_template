# Быстрый старт

Это руководство проводит от пустого сервера до работающей сети: один hub, несколько подключённых к нему серверов и телефон или ноутбук. На каждом шаге объясняется, что происходит на машине, чтобы ничего не стало сюрпризом.

## Требования

| Что | Подробности |
|---|---|
| ОС | Ubuntu 20.04+ или Debian 11+ (проверено: Ubuntu 22.04, 24.04, 26.04) |
| Оболочка | bash 4.4 или новее |
| Ядро | модуль `wireguard` (есть во всех поддерживаемых ядрах Ubuntu) |
| Init | рекомендуется systemd; без него интерфейсы управляются через `wg-quick` напрямую, а защита от перезагрузки недоступна |
| Пакеты | `wireguard-tools` (ставится автоматически через `apt-get`, если его нет), `iproute2`, `iptables` (только для маршрутизации и NAT на hub), `curl` или `wget` для установки |
| Права | root (`sudo`) для всех команд, кроме `help` и `version` |
| Сеть | у hub должен быть доступен снаружи один UDP-порт (по умолчанию 51820) |

Доступным снаружи должен быть только hub. Peer могут находиться за NAT: они сами подключаются к hub и поддерживают соединение keepalive-пакетами.

## Установка

Выполни на каждом сервере, который войдёт в сеть:

```bash
curl -fsSL https://raw.githubusercontent.com/Ange1oc/devops_template/main/ubuntu/wg/install.sh | sudo bash
```

Для воспроизводимой установки укажи тег или commit:

```bash
curl -fsSL https://raw.githubusercontent.com/Ange1oc/devops_template/main/ubuntu/wg/install.sh | sudo bash -s -- --ref <commit-sha>
```

Что делает установщик:

1. Скачивает архив репозитория по HTTPS (TLS 1.2+) и берёт из него только `ubuntu/wg`.
2. Отказывается устанавливать дерево, в котором есть симлинки.
3. Копирует его в промежуточный каталог с владельцем root, проверяет каждый скрипт через `bash -n` и один раз запускает новую версию.
4. Только после этого атомарно подменяет `/opt/wg-network`, а предыдущую версию сохраняет в `/opt/wg-network.old`.
5. Создаёт ссылку `/usr/local/bin/wg-network`, ставит автодополнение bash и systemd-таймер `wg-network-reresolve.timer`.

Установщик не трогает сеть: ни один интерфейс не создаётся и не перезапускается.

Проверка установки:

```bash
wg-network version
sudo wg-network help
```

> Тесты не устанавливаются. Каталог установки должен принадлежать root и быть недоступен на запись другим пользователям: команды, которые root выполнит позже (таймер отката, проверка при загрузке), запускаются оттуда. Копия в домашнем каталоге работает, но wg-network предупредит об этом и не установит защиту от перезагрузки.

## Создание hub

Выбери сервер с публичным адресом. `--endpoint` — адрес, по которому к нему будут подключаться peer: публичный IP или, лучше, DNS-имя.

```bash
sudo wg-network init hub --endpoint vpn.example.com
```

По умолчанию сеть туннеля `10.50.0.0/24`, адрес hub `10.50.0.1`, UDP-порт `51820`. Изменить: `--address 10.60.0.1/24`, `--port 51821`.

Что ты увидишь:

1. **Проверки.** wg-network откажется работать, если `/etc/wireguard/wg0.conf` уже существует и создан не им, если интерфейс `wg0` уже есть, если UDP-порт занят или сеть пересекается с маршрутом сервера (LAN, Docker, другой VPN). Так защищаются VPN, которые уже работают на машине.
2. **План.** Список изменений и способ применения («запуск wg0»).
3. **Вопрос**, применять ли. Без терминала (cron, CI) ответ — «нет»: изменение только готовится. В автоматизации используй `--yes`.
4. **Подтверждение.** Запуск интерфейса может повлиять на доступ к серверу, поэтому после запуска есть `CONFIRM_TIMEOUT` секунд (по умолчанию 120), чтобы подтвердить. В интерактивной сессии введи `yes`. Без подтверждения прежнее состояние вернётся автоматически, даже если SSH-сессия оборвалась.
5. **Firewall.** Если активен UFW, UDP-порт открывается в нём. При firewalld будет напечатана команда, которую нужно выполнить самому. Облачный security group открываешь ты.

Результат: интерфейс `wg0` поднят и включён в автозагрузку (`wg-quick@wg0`), конфиг `/etc/wireguard/wg0.conf` сгенерирован из состояния в `/etc/wireguard/wg-network/wg0/`.

```bash
sudo wg-network status
```

По умолчанию peer видят только hub (изоляция). Чтобы они видели друг друга, см. [Маршрутизация между peer](scenarios.md#маршрутизация-между-peer).

## Подключение сервера

Есть два способа: одна команда с hub по SSH или вручную с токеном.

### Одной командой с hub (deploy)

Требование: с hub можно зайти на новый сервер по SSH-ключу (без интерактивного ввода) под root или пользователем с `sudo` без пароля.

```bash
sudo wg-network deploy worker1 root@203.0.113.21 --install
```

Шаги, каждый печатается по ходу:

1. **invite**: для `worker1` резервируется адрес в туннеле и создаётся токен приглашения.
2. **установка** (`--install`): на удалённый сервер ставится wg-network тем же установщиком.
3. **join**: удалённый сервер подключается к сети. Токен передаётся через stdin SSH-сессии и не попадает ни в командную строку, ни в историю.
4. **peer add**: публичный ключ сервера добавляется на hub. Изменение горячее: остальные туннели не прерываются.
5. **handshake**: wg-network ждёт первый handshake до 20 секунд (`--wait N`) и честно сообщает, работает ли соединение. Код выхода 6 — «применено, но handshake пока не было».

Если установка или join не удались, резервация снимается, а сообщение объясняет, что произошло. Предохранители удалённой стороны продолжают работать: например, full tunnel, который отрезал бы SSH-доступ к тому серверу, там будет отклонён.

### Вручную с токеном

На hub:

```bash
sudo wg-network invite worker1
```

Команда резервирует адрес и печатает две команды для нового сервера, а токен — отдельной строкой. На новом сервере:

```bash
curl -fsSL https://raw.githubusercontent.com/Ange1oc/devops_template/main/ubuntu/wg/install.sh | sudo bash
sudo wg-network join
```

`join` запрашивает токен со скрытым вводом (его можно передать и через pipe: `printf '%s\n' "$TOKEN" | sudo wg-network join -`, или файлом `--token-file FILE`). Команда настраивает сторону peer, поднимает интерфейс и печатает команду для hub:

```bash
sudo wg-network peer add worker1 --key 'Xy...='
```

Выполни её на hub. Соединение установится примерно за 5 секунд (peer повторяет handshake раз в `REKEY_TIMEOUT`).

> **Токен — секрет.** В нём preshared key этого peer. Не публикуй его в чатах и тикетах. Передать токен аргументом (`join wgn1....`) можно, но будет предупреждение: аргументы видны всем пользователям сервера через `ps`.

## Подключение ноутбука или телефона

Устройства без wg-network получают готовый клиентский конфиг. Ключи генерируются на hub, приватный ключ там **не** сохраняется:

```bash
sudo wg-network peer add phone --generate --qr --dns 1.1.1.1
sudo wg-network peer add laptop --generate --output /root/laptop.conf
```

- `--qr` печатает QR-код для мобильного приложения WireGuard (нужен `qrencode`).
- `--output FILE` записывает конфиг с правами 600 и отказывается писать через существующий файл или симлинк.
- Без этих опций конфиг выводится в stdout. Сохрани его сразу: показать его повторно нельзя.

Чтобы весь трафик устройства шёл через hub (exit node), см. [Exit node](scenarios.md#exit-node-интернет-через-hub).

## Проверка

```bash
sudo wg-network status        # роль, адреса, ожидающие изменения, таблица peer
sudo wg-network peer list     # NAME ADDRESS STATE ENDPOINT HANDSHAKE RX TX ROUTES
sudo wg-network doctor        # полная самопроверка; код 0 — всё в порядке, 1 — предупреждения, 2 — ошибки
```

Состояния peer: `online` (handshake не старше 3 минут), `stale` (старше), `no-handshake` (ни разу), `down` (интерфейс не запущен), `disabled` (отключён), `invited` (зарезервирован, ждёт `peer add`).

С peer проверь связь с hub: `ping 10.50.0.1`.
