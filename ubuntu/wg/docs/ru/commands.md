# Справочник команд

```
wg-network [ГЛОБАЛЬНЫЕ ОПЦИИ] <команда> [ОПЦИИ]
wg-network help                     список команд
wg-network <команда> --help         справка по команде
```

Команды из двух слов можно писать любым способом: `peer add` или `peer-add`, `init hub` или `init-hub`. Синонимы: `diff` = `plan`; `ls`, `list`, `peers` = `peer list`; `token` = `invite`.

Все команды, кроме `help` и `version`, требуют root. Сообщения идут в stderr, в stdout — только данные (ключи, токены, конфиги, JSON), поэтому stdout можно безопасно перехватывать.

## Глобальные опции

Глобальные опции допускаются в любом месте командной строки.

| Опция | Значение |
|---|---|
| `-i, --interface IFACE` | интерфейс. По умолчанию — единственный управляемый; если их несколько — `DEFAULT_INTERFACE`, когда он среди них, иначе `-i` обязателен |
| `-n, --dry-run` | выполнить на копии состояния и показать план; система не меняется |
| `--apply` | применить без вопроса (предохранители продолжают работать) |
| `--no-apply` | только подготовить изменение; применить позже: `wg-network apply` |
| `-y, --yes` | ответить «да» на все вопросы, включая ввод имени интерфейса; подтвердить изменение автоматически после пост-проверок, если SSH не затронут |
| `--force` | снять блокировку предохранителя (уровень 2) или отказ; подтверждение и таймер отката остаются |
| `--wait-confirm` | никогда не подтверждать автоматически, даже с `--yes`: ждать `wg-network confirm` |
| `--confirm-timeout N` | секунд до отката неподтверждённого изменения (по умолчанию `CONFIRM_TIMEOUT`, 0 — без таймера) |
| `--diff` | дополнительно показать diff конфига (секреты скрыты) |
| `-q, --quiet` | выводить только предупреждения и ошибки |
| `--no-color` | без цвета (также при `NO_COLOR` или если stderr не терминал) |
| `-V, --version` | то же, что `version` |
| `-h, --help` | справка |

## Коды выхода

| Код | Значение |
|---|---|
| 0 | успех, в том числе «подготовлено, но не применено» и «применено, ждёт подтверждения» |
| 1 | ошибка |
| 2 | неверные аргументы или `--dry-run` с командой, которая его не поддерживает |
| 3 | отказ предохранителя или пользователя |
| 4 | изменение не применено: сбой или нет подтверждения, прежняя конфигурация восстановлена |
| 5 | занято: блокировку держит другой wg-network или изменение ждёт подтверждения |
| 6 | `peer add --wait`, `deploy`: применено, но handshake за отведённое время не произошёл |
| 10 | `plan`: есть неприменённые изменения |
| 129, 130, 143 | прервано сигналом SIGHUP, SIGINT, SIGTERM (транзакция откатывается) |

У `doctor` свои коды: 0 — всё в порядке, 1 — предупреждения, 2 — ошибки.

Итог изменения печатается и словами: «применено», «применено, ждёт подтверждения», «записано в конфиг, интерфейс остановлен», «сохранено, но НЕ применено», «dry-run». В JSON тот же итог — `applied`, `pending`, `written`, `prepared`, `dry-run`.

## Файл настроек

`/etc/default/wg-network` необязателен. Формат `KEY=VALUE`; файл разбирается, а не исполняется, каждое значение проверяется.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `DEFAULT_INTERFACE` | `wg0` | интерфейс, если не указан `-i` и выбрать больше не из чего |
| `DEFAULT_HUB_ADDRESS` | `10.50.0.1/24` | адрес hub и сеть для `init hub` |
| `DEFAULT_PORT` | `51820` | UDP-порт для `init hub` |
| `DEFAULT_KEEPALIVE` | `25` | `PersistentKeepalive` от peer к hub и для сгенерированных клиентов |
| `CONFIRM_TIMEOUT` | `120` | секунд на подтверждение; 0 отключает таймер отката |
| `AUTO_APPLY` | `ask` | `ask` — спрашивать; `hot` — горячие изменения применять без вопроса; `never` — только готовить |
| `SNAPSHOT_KEEP` | `30` | сколько снимков хранить на интерфейс |
| `LOCK_WAIT` | `30` | секунд ожидания блокировки интерфейса |
| `RERESOLVE_AFTER` | `135` | секунд без handshake до повторного DNS-резолва endpoint |

## Настройка узла

### init hub

```
wg-network [-i IFACE] init hub --endpoint HOST[:PORT] [опции]
```

Делает этот сервер hub сети.

| Опция | Значение |
|---|---|
| `--endpoint HOST[:PORT]` | **обязательна.** Публичный IP или DNS-имя для подключения peer. Порт по умолчанию — `--port`; другой порт принимается с предупреждением (проброс портов) |
| `--address IP/LEN` | адрес hub и размер сети, префикс 8–30 (по умолчанию `10.50.0.1/24`) |
| `--address6 CIDR\|auto` | включить dual-stack IPv6. `auto` — случайный ULA /64 (RFC 4193); сеть вида `fd00::/64` превращается в `fd00::1/64` |
| `--port N` | UDP-порт (по умолчанию 51820) |
| `--forward` | маршрутизировать трафик между peer через hub (по умолчанию peer видят только hub) |
| `--nat IFACE` | выпускать peer в интернет через `IFACE` (MASQUERADE, exit node) |
| `--mtu N` | MTU туннеля, 1280–9000 (по умолчанию вычисляет `wg-quick`) |
| `--table auto\|off\|N` | `Table=` для `wg-quick`: куда ставить маршруты |
| `--name NAME` | имя узла (по умолчанию `hub`) |
| `--no-firewall` | не открывать порт в UFW |
| `--force` | переинициализировать управляемый интерфейс (ключ и peer сохраняются) или заменить чужой конфиг |

Поведение:

- Отказ, если интерфейс уже управляется (используй `set`, или `--force` для переинициализации), если есть чужой `<iface>.conf` или интерфейс, если порт занят или сеть пересекается с локальным маршрутом.
- При необходимости ставит `wireguard-tools` через `apt-get`.
- Генерирует ключ один раз; переинициализация с `--force` его сохраняет.
- Запускает интерфейс под таймером отката, включает `wg-quick@<iface>` в автозагрузку и ставит drop-in отката при загрузке.
- Открывает UDP-порт в UFW, если UFW активен (и запоминает это в `FIREWALL_PORT`). При firewalld печатает команду.

Маршрутизация (`--forward`, `--nat`) делается через sysctl форвардинга на конкретных интерфейсах и правила iptables в `PostUp`/`PostDown` с комментарием `wg-network`. TCP MSS ограничивается по MTU пути. Глобальный `ip_forward` не меняется.

### init peer

```
wg-network [-i IFACE] init peer --name NAME --address IP --hub-key KEY --endpoint HOST:PORT [опции]
```

Подключает этот сервер к hub без токена (если все значения известны). Обычно проще `join`.

| Опция | Значение |
|---|---|
| `--name NAME` | **обязательна.** Имя этого сервера в сети |
| `--address IP` | **обязательна.** IPv4-адрес этого сервера в туннеле (синоним `--ip`) |
| `--address6 IP` | IPv6-адрес в туннеле, если сеть dual-stack |
| `--hub-key KEY` | **обязательна.** Публичный ключ hub (`wg-network public-key` на hub) |
| `--endpoint HOST:PORT` | **обязательна.** Публичный endpoint hub |
| `--routes CIDR,...` | что отправлять через hub (по умолчанию адрес hub из `DEFAULT_HUB_ADDRESS`, /32) |
| `--psk-file FILE` | файл с preshared key, если он задан на hub для этого peer |
| `--keepalive N` | `PersistentKeepalive`, 0 — выключить (по умолчанию 25) |
| `--mtu N`, `--table T` | как в `init hub` |
| `--force` | переинициализировать этот узел |

Печатает команду `peer add` для hub (с `--address`).

### join

```
wg-network [-i IFACE] join [TOKEN | - | --token-file FILE] [--json] [--force]
```

Подключает этот сервер к hub по токену из `invite`.

- Без аргумента токен запрашивается со скрытым вводом или читается из stdin, если stdin не терминал.
- `-` читает токен из stdin: `printf '%s\n' "$TOKEN" | sudo wg-network join -`.
- `--token-file FILE` читает его из файла.
- Токен в аргументе работает, но с предупреждением: аргументы видны другим пользователям через `ps`.
- `--json` печатает итог в stdout (см. [JSON-вывод](#json-вывод)).
- `--force` переинициализирует уже управляемый узел.

Токен проверяется поле за полем. Интерфейс запускается под таймером отката. С `--dry-run` план показывается, но команда `peer add` не печатается: ключ в ней был бы ключом песочницы, а не этого сервера.

### set

```
wg-network [-i IFACE] set [опции]
```

Меняет параметры узла.

| Опция | Узел | Значение |
|---|---|---|
| `--endpoint HOST[:PORT]` | hub | публичный endpoint для новых приглашений. На работающие peer не влияет |
| `--port N` | hub | UDP-порт. Каждому peer потом нужен `peer set hub --endpoint HOST:N`. При существующих peer нужно ввести имя интерфейса (или `--yes`) |
| `--forward on\|off` | hub | маршрутизация между peer |
| `--nat IFACE\|off` | hub | выход peer в интернет через `IFACE` |
| `--mtu N\|auto` | любой | MTU туннеля |
| `--table auto\|off\|N` | любой | `Table=` для `wg-quick` |
| `--no-firewall` | hub | не открывать новый порт в UFW |

Почти любая опция меняет `[Interface]`, поэтому применение перезапускает интерфейс под таймером отката. Смена `--forward` не меняет маршруты, уже выданные существующим peer; поправь их на каждом peer: `peer set hub --routes ...`. Старое правило UFW после смены порта не удаляется: убери его, когда peer переедут.

## Peer

### invite

```
wg-network [-i IFACE] invite NAME [опции]
```

На hub: резервирует адрес для нового сервера и печатает команды для него и токен.

| Опция | Значение |
|---|---|
| `--address IP` | адрес нового peer (по умолчанию первый свободный) |
| `--routes CIDR,...` | сети за этим peer (site-to-site); hub будет направлять их в него |
| `--full-tunnel` | peer отправляет через hub весь трафик (нужен `--nat` на hub или `--force`) |
| `--keepalive N` | `PersistentKeepalive` на стороне peer (по умолчанию 25) |
| `--no-psk` | без preshared key |
| `--comment TEXT` | комментарий |
| `--json` | итог с токеном в stdout |

До `peer add` резервация не попадает в конфиг, но адрес остаётся занятым для других приглашений. Повторный `invite` для зарезервированного имени перевыпускает токен с тем же адресом и preshared key. IPv6-адрес peer (dual-stack) выводится из номера хоста в IPv4: `10.50.0.7` даёт `<префикс>::7`.

### deploy

```
wg-network [-i IFACE] deploy NAME [USER@]HOST [опции]
```

На hub: подключает удалённый сервер одной командой по SSH: `invite`, при необходимости установка, `join` на удалённом сервере, `peer add` здесь и ожидание handshake.

| Опция | Значение |
|---|---|
| `--install` | сначала установить wg-network на удалённый сервер |
| `--remote-iface IFACE` | интерфейс на удалённом сервере (по умолчанию `wg0`) |
| `--ssh-option OPT` | опция `ssh -o`, можно несколько: `--ssh-option Port=2222` |
| `--routes`, `--full-tunnel`, `--keepalive N`, `--no-psk`, `--comment TEXT` | как в `invite` |
| `--wait N` | ждать handshake до N секунд (по умолчанию 20; 0 — не ждать) |

Требования: вход по SSH-ключу (`BatchMode=yes`, таймаут подключения 15 с) под root или пользователем с `sudo` без пароля (`sudo -n`). Токен передаётся через stdin SSH-сессии. Если установка или join не удались, резервация снимается. Если удалённая сторона подготовила изменение, но не применила его (например, предохранитель там потребовал подтверждения), резервация остаётся, и об этом сообщается. Код 6 — peer добавлен, но handshake вовремя не произошёл. `--dry-run` не поддерживается.

### peer add

```
wg-network [-i IFACE] peer add NAME (--key KEY | --generate) [опции]
```

На hub: добавляет peer или завершает приглашение.

| Опция | Значение |
|---|---|
| `--key KEY` | публичный ключ peer (его печатает `join`/`init peer`) |
| `--generate` | сгенерировать ключи здесь и выдать готовый клиентский конфиг (для ноутбуков и телефонов; приватный ключ на hub не хранится) |
| `--address IP` | адрес (по умолчанию из приглашения или первый свободный) |
| `--routes CIDR,...` | сети за этим peer |
| `--psk` / `--no-psk` | preshared key. По умолчанию: да для `--generate`, иначе как в приглашении |
| `--endpoint HOST:PORT` | адрес peer, если hub должен сам инициировать соединение |
| `--keepalive N` | `PersistentKeepalive` со стороны hub (обычно не нужен) |
| `--comment TEXT` | комментарий |
| `--wait N` | ждать первый handshake до N секунд; код 6, если его нет |
| `--json` | итог в stdout |
| `--output FILE` | только `--generate`: записать клиентский конфиг в FILE (права 600; существующий файл — только с `--force`) |
| `--qr` | только `--generate`: показать QR-код (нужен `qrencode`) |
| `--dns IP[,IP]` | только `--generate`: DNS-серверы для клиента |
| `--full-tunnel` | только `--generate`: весь трафик клиента через hub (нужен NAT на hub) |

Добавление peer — горячее изменение: остальные туннели не прерываются. Отказ, если имя уже есть (используй `peer set`), если ключ принадлежит другому peer или самому hub, если адрес или маршруты конфликтуют.

### peer set

```
wg-network [-i IFACE] peer set NAME [опции]
```

Меняет peer. На узле-peer запись hub называется `hub`.

| Опция | Значение |
|---|---|
| `--key KEY` | новый публичный ключ (переустановленный сервер) |
| `--routes CIDR,...\|none` | сети за peer; `none` — убрать. На узле-peer: что отправлять через hub (хотя бы один маршрут должен остаться) |
| `--endpoint HOST:PORT\|none` | endpoint peer. На узле-peer: новый адрес hub |
| `--keepalive N` | `PersistentKeepalive`, 0 — выключить |
| `--comment TEXT` | комментарий |
| `--rotate-psk` | сгенерировать новый preshared key и напечатать его в stdout; его нужно задать и на самом peer |
| `--psk-file FILE\|-` | задать preshared key из файла или stdin (вторая половина ротации) |

Примеры:

```bash
sudo wg-network peer set hub --endpoint 198.51.100.20:51820   # на peer: hub переехал
sudo wg-network peer set office --routes 192.168.10.0/24,192.168.20.0/24
ssh hub sudo wg-network peer set worker1 --rotate-psk --yes | ssh worker1 sudo wg-network peer set hub --psk-file - --yes
```

### peer remove

```
wg-network [-i IFACE] peer remove NAME
```

Удаляет peer или приглашение. Peer отключается сразу после применения, остальные туннели продолжают работать. Запись остаётся в снимке: `wg-network rollback` вернёт её, а последний известный адрес peer используется для немедленного переподключения.

### peer enable / peer disable

```
wg-network [-i IFACE] peer disable NAME
wg-network [-i IFACE] peer enable NAME
```

Отключает peer с сохранением настроек (он пропадает из конфига) или включает обратно. Незавершённое приглашение нельзя включить или отключить.

### peer list

```
wg-network [-i IFACE] peer list [--json]
```

Таблица `NAME ADDRESS STATE ENDPOINT HANDSHAKE RX TX ROUTES`.

| Состояние | Значение |
|---|---|
| `online` | последний handshake не старше 3 минут |
| `stale` | старше 3 минут: недоступен или простаивает |
| `no-handshake` | ни разу не подключался |
| `down` | интерфейс не запущен |
| `disabled` | отключён через `peer disable` |
| `invited` | зарезервирован через `invite`, ждёт `peer add` |

### peer show

```
wg-network [-i IFACE] peer show NAME
```

Подробности об одном peer: состояние, публичный ключ, есть ли preshared key, адреса, AllowedIPs, endpoint, keepalive, последний handshake, трафик, комментарий, время создания.

## Применение и откат

### plan

```
wg-network [-i IFACE] plan [--diff]
```

Сравнивает действующий конфиг с конфигом из состояния и показывает изменения, способ их применения и предупреждения предохранителей. Ничего не меняет. Код 0 — применять нечего (в том числе если отличается только оформление файла, например шапка после обновления: следующее применение перепишет его, не трогая интерфейс); код 10 — есть неприменённые изменения (удобно для мониторинга и CI). Также предупреждает о ручных правках и ожидающем подтверждении.

### apply

```
wg-network [-i IFACE] apply [--start] [--diff]
```

Применяет подготовленные изменения. Сам запуск `apply` — это разрешение; предохранители всё равно спрашивают своё подтверждение. `--start` запускает остановленный интерфейс (без него у остановленного интерфейса только записывается файл). `apply` также возвращает ядро к конфигу, если кто-то менял peer через `wg set`.

### confirm

```
wg-network [-i IFACE] confirm
```

Подтверждает применённое изменение и отменяет таймер отката. Запускай из **новой** SSH-сессии: так подтверждается, что доступ после изменения есть.

### rollback

```
wg-network [-i IFACE] rollback              неподтверждённое изменение — сразу; иначе последний снимок
wg-network [-i IFACE] rollback SNAPSHOT     вернуться к снимку (см. history)
```

- Если изменение ждёт подтверждения, `rollback` сразу возвращает прежний конфиг и прежнее состояние.
- Иначе `rollback` возвращает желаемое состояние к последнему снимку и применяет его как обычное изменение (план, предохранители, таймер). Снимок делается перед каждым изменением, поэтому это отменяет последнее изменение; повторный запуск отменяет сам откат.
- `rollback SNAPSHOT` возвращает к любому снимку из `history`, в том числе к снимку `rejected` (изменение, которое не удалось или не было подтверждено) — так его можно повторить.
- Снимок, сделанный до появления интерфейса, вернуть нельзя; чтобы убрать интерфейс, используй `destroy`.

Служебные режимы для таймера и загрузки: `--pending [--txid ID] [--auto | --boot]`.

### history

```
wg-network [-i IFACE] history
```

Снимки от новых к старым и операция, перед которой сделан каждый (`peer-add`, `set`, `rollback`, `rejected`, ...). В идентификаторе снимка есть дата и время.

## Состояние и диагностика

### status

```
wg-network [-i IFACE] status [--json]
```

Состояние интерфейса и юнита systemd, роль, имя, публичный ключ, адреса, endpoint и порт, режим маршрутизации, MTU и таблица; предупреждения об ожидающем подтверждении, ручных правках, неприменённых изменениях и повреждённом состоянии; затем таблица peer.

### doctor

```
wg-network [-i IFACE] doctor
```

Самопроверка, только чтение. Код 0 — всё в порядке, 1 — предупреждения, 2 — ошибки.

| Раздел | Что проверяется |
|---|---|
| Окружение | `wg`, `wg-quick`, `ip`, `ss`, `flock`; модуль ядра `wireguard`; запущенный `wireguard-go` (медленный userspace); systemd; синхронизация времени (NTP) |
| Состояние | проверка всех файлов; права 700/600; прерванная транзакция; ожидающее подтверждение; пересечения AllowedIPs |
| Конфиг | наличие и права действующего конфига; ручные правки; неприменённые изменения; `wg-quick@` в автозагрузке; drop-in отката при загрузке |
| Интерфейс | запущен; peer в ядре совпадают с конфигом; порт; маршруты для AllowedIPs; MTU больше 1420 |
| Сеть и firewall | UFW или правила при `INPUT DROP` для порта; sysctl форвардинга; правила FORWARD, MASQUERADE и MSS; глобальный IPv6-форвардинг для dual-stack; заполнение conntrack на exit node; SSH-сессии через интерфейс |
| Peer | состояние и возраст handshake каждого peer; DNS-резолв endpoint с именем хоста |

### show

```
wg-network [-i IFACE] show [--candidate] [--reveal]
```

Печатает действующий конфиг (`--candidate` — конфиг, который запишет следующий `apply`). `PrivateKey` и `PresharedKey` скрыты без `--reveal`.

### interfaces

```
wg-network interfaces
```

Все управляемые интерфейсы: `IFACE ROLE ADDRESS STATE PEERS`.

### public-key

```
wg-network [-i IFACE] public-key
```

Печатает публичный ключ интерфейса (только stdout).

## Обслуживание

### backup

```
wg-network [-i IFACE] backup [--output FILE]
```

Пишет tar-архив состояния: `node.env`, `private.key`, `peers.d` и `meta.env` (формат `wgn-backup-1`). Без `--output` архив идёт в stdout, который не должен быть терминалом. В архиве приватный ключ и preshared key: храни его зашифрованным, например `wg-network backup | gpg -c > wg0.backup.gpg`. `--output` создаёт файл с правами 600 и отказывается писать через существующий файл или симлинк без `--force`.

### restore

```
wg-network [-i IFACE] restore FILE|- [--force] [--no-firewall]
```

Восстанавливает интерфейс из архива, обычно на сервере-замене. Архив должен содержать только файлы состояния (никаких абсолютных путей, `..`, симлинков и устройств) и проверяется теми же правилами, что и рабочее состояние, до того как что-либо записано. Затем интерфейс запускается обычным путём: план, предохранители, таймер. Управляемый интерфейс заменяется только с `--force`; его текущее состояние остаётся в снимке. Сервер получает тот же ключ, поэтому peer переподключаются, как только DNS-имя hub укажет на него.

### destroy

```
wg-network -i IFACE destroy
```

Останавливает и отключает интерфейс, сохраняет архив его состояния и конфига в `/var/backups/wg-network/<iface>-<время>.tar` (права 600) и удаляет их вместе с drop-in загрузки. Интерфейс нужно указать явно через `-i` и ввести его имя (или `--yes`). Ожидающее подтверждение отменяется. Правило UFW, открытое wg-network, остаётся; команда для его удаления печатается.

### reresolve

```
wg-network reresolve
```

WireGuard резолвит DNS-имя endpoint один раз. Для каждого включённого peer с endpoint-именем и без handshake дольше `RERESOLVE_AFTER` секунд endpoint задаётся заново, то есть резолвится повторно (как `reresolve-dns` из wireguard-tools). Запускается раз в минуту таймером `wg-network-reresolve.timer` в захардненном юните; вручную нужна редко.

### self-update

```
wg-network self-update [--ref REF]
```

Переустанавливает wg-network из того репозитория и ref, из которых он был установлен (или `--ref`). Меняется только программа: ключи, конфиги и интерфейсы не трогаются. Отменить: `sudo /opt/wg-network/install.sh --rollback`.

### version

```
wg-network version
```

Версия, путь установки, репозиторий, ref, commit, время установки и версия `wireguard-tools`.

## Установщик (install.sh)

```
install.sh [--ref REF] [--repo OWNER/REPO] [--local [DIR]] [--rollback] [--uninstall]
```

| Опция | Значение |
|---|---|
| `--ref REF` | ветка, тег или commit (по умолчанию `main`) |
| `--repo OWNER/REPO` | другой репозиторий, например форк (по умолчанию `Ange1oc/devops_template`) |
| `--local [DIR]` | установить из локальной копии (по умолчанию — каталог `install.sh`) |
| `--rollback` | вернуться к предыдущей версии из `/opt/wg-network.old` |
| `--uninstall` | удалить программу, юниты и drop-in; интерфейсы продолжают работать, состояние остаётся в `/etc/wireguard/wg-network` |

Переменные окружения: `WGN_REPO`, `WGN_REF` задают значения по умолчанию; `GITHUB_TOKEN` даёт доступ к приватному репозиторию (нужен `curl`; токен передаётся через файл заголовков, а не командной строкой). Две установки одновременно не запустятся.

## JSON-вывод

JSON выводится в stdout одним объектом или массивом на команду.

`invite --json`:

```json
{"name":"worker1","address":"10.50.0.2","address6":"","token":"wgn1....","install_command":"curl -fsSL ... | sudo bash -s -- --ref main","join_command":"sudo wg-network join"}
```

`join --json`:

```json
{"name":"worker1","address":"10.50.0.2","public_key":"...","interface":"wg0","result":"applied","approve_command":"sudo wg-network peer add worker1 --key ..."}
```

`peer add --json` (`handshake` — `true`/`false` с `--wait`, иначе `null`):

```json
{"name":"worker1","address":"10.50.0.2","public_key":"...","result":"applied","handshake":true}
```

`peer list --json` — массив peer:

```json
[{"name":"worker1","public_key":"...","address":"10.50.0.2","address6":"","routes":"","endpoint":"203.0.113.21:43122","state":"online","latest_handshake":1767225600,"rx_bytes":1234,"tx_bytes":5678,"comment":""}]
```

`status --json`:

```json
{"interface":"wg0","role":"hub","name":"hub","public_key":"...","address":"10.50.0.1/24","address6":"",
 "listen_port":51820,"endpoint":"vpn.example.com:51820","forward":false,"nat":"","unit":"active","up":true,
 "state_valid":true,"pending_confirmation":false,"manual_edits":false,"unapplied_changes":false,"peers":[...]}
```

`latest_handshake` — Unix-время, 0 — «ни разу», `null` — интерфейс не запущен или peer нет в ядре (приглашён, отключён). `state_valid` равно `false`, если файл состояния повреждён; `unapplied_changes` тогда `false`, потому что план построить нельзя.
