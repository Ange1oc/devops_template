# Использование

```
ubuntu-bootstrap [глобальные опции] <команда> [аргументы команды]
ubuntu-bootstrap help [команда]
ubuntu-bootstrap <команда> --help
```

Глобальные опции ставятся **перед** командой. Root (`sudo`) нужен всем командам, кроме `help`, `version`, `modules`, `profiles` и `doctor`: даже `plan` читает `sshd -T`, состояние модулей и пишет журнал запуска. Без root с `--dry-run` можно проверить файл конфигурации или профиль: `ubuntu-bootstrap --dry-run --config server.conf config validate`.

## Глобальные опции

| Опция | Назначение |
|---|---|
| `-p, --profile NAME` | профиль: `minimal`, `web`, `docker`, `full` или свой из `/etc/ubuntu-bootstrap/profiles.d/`. Задаёт набор модулей и умолчания опций. Имеет приоритет над `PROFILE=` в файле конфигурации |
| `-c, --config FILE` | файл конфигурации вместо `/etc/ubuntu-bootstrap/bootstrap.conf` |
| `-s, --set KEY=VALUE` | переопределить опцию; можно повторять. Значение с пробелами берётся в кавычки целиком: `--set 'ADMIN_SSH_KEYS=ssh-ed25519 AAAA... me'` |
| `--only M1,M2` | выполнить только эти модули и их зависимости (вместо набора из конфига) |
| `--skip M1,M2` | исключить модули из набора |
| `-n, --dry-run` | ничего не менять: показать diff файлов и команды. `plan` — то же самое, что `apply --dry-run` |
| `-y, --yes` | неинтерактивный режим: вопросы получают ответ по умолчанию, опасные действия (`confirm_danger`) считаются подтверждёнными. **Предохранители при этом продолжают работать** — их снимает только `--force` |
| `--keep-going` | при ошибке или отказе модуля продолжать со следующего (по умолчанию запуск останавливается) |
| `--force` | снять предохранители: неподдерживаемая версия Ubuntu, отсутствие ключей или sudo у администратора, занятый порт, `*_CONFIRM=none` и т.д. Подтверждения и таймер отката при этом остаются |
| `-q, --quiet` | только предупреждения и ошибки |
| `-v, --verbose` | подробный вывод (каждый записанный файл, смена прав) |
| `--json` | машиночитаемый вывод для `status`, `audit`, `modules`, `version` |
| `--no-color` | без цветов (также учитывается переменная `NO_COLOR`) |
| `-V, --version` | то же, что команда `version` |

## Команды

### `wizard [--advanced]`

Интерактивный мастер. Нужен терминал (работает и через `curl ... | sudo bash -s -- --run`, читая `/dev/tty`). Шаги:

1. Обзор сервера: ОС, виртуализация, ресурсы, сеть, текущая SSH-сессия и порты sshd.
2. Выбор профиля (или свой набор без профиля). Если `/etc/ubuntu-bootstrap/bootstrap.conf` уже есть, его значения предлагаются по умолчанию.
3. Включение/выключение каждого модуля; зависимости включаются автоматически, `preflight` выполняется всегда.
4. Опции каждого включённого модуля с подсказками и валидацией. Опции с пометкой «дополнительные» задаются только при ответе «да» на соответствующий вопрос или с `--advanced`.
5. Сохранение `/etc/ubuntu-bootstrap/bootstrap.conf` (со всеми опциями и описаниями).
6. План (dry-run): diff файлов и команды, которые будут выполнены.
7. Применение. Для рискованных модулей мастер попросит открыть новую SSH-сессию и подтвердить, что вход работает; иначе через заданное время изменения откатятся.

До шага 5 система не меняется. Повторный запуск мастера читает сохранённую конфигурацию, поэтому его можно использовать и для изменения настроек.

### `plan`

Dry-run: все модули проходят свои проверки и предохранители, печатают diff файлов (секреты маскируются) и команды, но ничего не меняют. Код выхода такой же, как был бы у `apply`: 3, если предохранитель остановил бы запуск. Модули помечают «планируемые факты» (например, что пользователь будет создан), поэтому план на чистом сервере проходит как настоящее применение.

### `apply [--reapply]`

Применяет модули из конфигурации (или `--only`) в порядке зависимостей. Для каждого модуля:

- если состояние `applied`, хэш опций не менялся и `mod_check` подтверждает желаемое состояние — модуль пропускается (`--reapply` отменяет пропуск; `preflight` выполняется всегда);
- иначе выполняется `mod_apply`, затем `mod_verify`; успех записывается в состояние модуля вместе с хэшем его опций;
- ошибка откатывает только изменения этого модуля (файлы из бэкапов и команды отката, в обратном порядке) и останавливает запуск; `--keep-going` продолжает со следующего модуля;
- остановка предохранителем (код 3) оставляет систему нетронутой: всё, что модуль успел записать до отказа, откатывается.

Если есть изменения, ожидающие подтверждения (`pending.env`), `apply` завершается кодом 5: сначала `confirm` или `rollback --pending`.

### `confirm`

Подтверждает рискованное изменение (смена SSH-порта, включение UFW) и снимает таймер отката. Выполняется **из новой сессии**, чтобы доказать, что доступ работает. После подтверждения модуль может выполнить отложенные действия: `ssh` закрывает в UFW старый порт.

### `rollback`

```
ubuntu-bootstrap rollback --pending [--auto|--boot]
ubuntu-bootstrap rollback RUN_ID [--module NAME]
ubuntu-bootstrap rollback --last [--module NAME]
```

- `--pending` — откатить изменения, ожидающие подтверждения (вызывается вручную, таймером с `--auto` и recover-сервисом с `--boot`).
- `RUN_ID` — откатить запуск из `history`: файлы восстанавливаются из его бэкапов, команды отката выполняются в обратном порядке; `--module` ограничивает откат одним модулем. Перед выполнением показывается журнал и запрашивается подтверждение (`--yes` принимает).
- `--last` — последний запуск.

Пакеты при откате не удаляются; откат касается конфигурации, правил и состояния сервисов.

### `status [--all] [--json]`

Для каждого выбранного (или всех с `--all`) модуля: `ok` — желаемое состояние достигнуто; `config-changed` — применён, но опции с тех пор изменились; `pending` — не применён или состояние не соответствует; `n/a` — не применяется в контейнере. Показывает дату применения и напоминает об ожидающем подтверждении. Код выхода 0, только если всё актуально.

### `audit [--all] [--json]`

Аудит безопасности и готовности, только чтение. Общесистемные проверки: версия Ubuntu, требуется ли перезагрузка, доступные обновления, сервисы в состоянии failed, пользователи с пустым паролем и UID 0, sudo без пароля, world-readable секреты в типовых местах, порты на всех интерфейсах, AppArmor, свободное место, крупные логи. Затем проверки каждого модуля (`mod_audit`). Код выхода: 0 — порядок, 1 — есть предупреждения, 2 — есть проблемы. `--json` — для мониторинга.

### `doctor [--json]`

Диагностика самого инструмента: ОС и архитектура, systemd, контейнер, нужные команды, занятость apt, доступ к `archive.ubuntu.com` по HTTPS, синтаксис всех файлов, метаданные установки, права на `/opt/ubuntu-bootstrap`, recover-сервис, свои модули, корректность конфига, запуски в состоянии `running`/`interrupted`, ожидающие подтверждения. Коды выхода как у `audit`.

### `history [RUN_ID]`

Без аргумента — таблица запусков (идентификатор, статус, команда, dry-run, модули). С `RUN_ID` — его `run.env` и журнал: записанные файлы (с пометкой «новый», если файла не было), удалённые файлы, команды отката, путь к логу и бэкапам.

Идентификатор запуска — `ГГГГММДД-ЧЧММСС-PID`. Статусы: `running`, `done`, `failed`, `refused` (остановлен предохранителем), `rolled_back`, `interrupted` (процесс прерван).

### `config <show|validate|get|set|init|path>`

| Подкоманда | Назначение |
|---|---|
| `show` | действующая конфигурация выбранных модулей и источник каждого значения: `profile:web`, `file:/etc/...`, `cli`, `default` |
| `validate` | проверить файл конфигурации и профиль; ошибка указывает ключ, значение, ожидаемый тип и источник |
| `get KEY` | напечатать действующее значение опции |
| `set KEY=VALUE...` | записать значения в `/etc/ubuntu-bootstrap/bootstrap.conf` (с валидацией и бэкапом прежнего файла) |
| `init [--profile NAME]` | создать файл конфигурации из профиля со всеми опциями и описаниями; существующий файл перезаписывается только с `--force` |
| `path` | путь к действующему файлу конфигурации |

### `modules [--options] [MODULE]`, `profiles [NAME]`

Справочники: таблица модулей (группа, входит ли в набор по умолчанию, зависимости), подробности одного модуля с опциями, все опции всех модулей (`--options`); список профилей с описанием и модулями, содержимое профиля.

### `self-update [--ref REF] [--check]`, `version [--json]`

См. [Установка](install.md#обновление).

## Коды выхода

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | ошибка (модуль откачен; подробности в выводе и логе) |
| 2 | неверное использование: неизвестная команда, аргумент или значение `--set` |
| 3 | остановлено предохранителем; `--force` снимает |
| 4 | изменения откачены: таймер подтверждения истёк, ответ «нет» или самопроверка не прошла |
| 5 | занято: другой процесс держит блокировку, apt/dpkg занят дольше лимита или есть изменения, ожидающие подтверждения |
| 130 | прервано сигналом (Ctrl-C, SIGTERM); запуск помечается `interrupted` |

`audit`, `doctor`: 0 / 1 (предупреждения) / 2 (проблемы). `status`: 0 — всё актуально, 1 — есть что применить или подтвердить.

## Конфигурация

Файл `/etc/ubuntu-bootstrap/bootstrap.conf` (права 600, владелец root):

```
# комментарии и пустые строки пропускаются
PROFILE=web
MODULES_SKIP=swap
ADMIN_USER=deploy
ADMIN_SSH_KEYS=ssh-ed25519 AAAA... admin@laptop;ssh-ed25519 BBBB... admin@desk
SSH_PORT=2222
```

Правила формата:

- одна пара `KEY=VALUE` в строке; ключ — заглавные буквы, цифры и `_`;
- значение берётся как есть до конца строки, без кавычек и экранирования; пробелы внутри значения допустимы;
- файл **никогда не исполняется** как shell-скрипт: подстановки, `$(...)` и прочее не работают;
- неизвестный ключ или значение неверного типа — ошибка с указанием источника;
- пустое значение для большинства опций означает «не задано» (см. описание опции).

Приоритет источников: `--set` > файл конфигурации > профиль > умолчание модуля. Команда `config show` печатает, откуда взято каждое значение.

Ключи ядра (не принадлежат модулям):

| Ключ | Назначение |
|---|---|
| `PROFILE` | имя профиля; его файл читается первым |
| `MODULES` | полный список модулей через запятую; заменяет список профиля и набор по умолчанию |
| `MODULES_ADD` | добавить модули к набору |
| `MODULES_SKIP` | исключить модули из набора |

Набор модулей: `MODULES` (или набор по умолчанию, если не задан) плюс `MODULES_ADD` минус `MODULES_SKIP`; затем добавляются зависимости и `preflight`. В командной строке `--only` заменяет набор целиком, `--skip` исключает.

### Типы опций

| Тип | Допустимые значения | Примеры |
|---|---|---|
| `bool` | `yes/no`, `true/false`, `on/off`, `1/0` | `yes` |
| `int` | целое ≥ 0 | `180` |
| `port` | 1–65535 | `2222` |
| `portkeep` | порт или `keep` (не менять) | `keep` |
| `string` | одна строка | `04:00` |
| `list` | элементы через запятую, точку с запятой или пробел | `curl,git jq` |
| `enum:a,b,c` | одно из перечисленных | `auto` |
| `user` / `users` | имя пользователя Linux (`^[a-z_][a-z0-9_-]{0,31}$`) / список | `deploy`, `deploy,ops` |
| `path` | абсолютный путь | `/swapfile` |
| `size` | число с суффиксом `M` или `G`; для некоторых опций ещё `auto` и `0` | `2G`, `512M` |
| `email` | адрес e-mail | `ops@example.com` |
| `duration` | интервал fail2ban/systemd | `10m`, `1h`, `2weeks`, `1month` |
| `timezone` | имя из `/usr/share/zoneinfo` | `Europe/Moscow` |
| `hostname` / `hostnames` | DNS-имя / список | `example.com,www.example.com` |
| `keys` | публичные SSH-ключи через `;` (ed25519, rsa, ecdsa, sk-*) | `ssh-ed25519 AAAA... a;ssh-rsa BBBB... b` |
| `ports` | список `PORT` или `PORT/tcp|udp` | `8443/tcp,51820/udp,9000` |
| `cidrs` | список IP или CIDR (IPv4/IPv6) | `203.0.113.0/24,2001:db8::1` |

### Профили

| Профиль | Модули | Опции профиля |
|---|---|---|
| `minimal` | preflight base time users ssh firewall fail2ban updates journald | — |
| `web` | minimal + sysctl limits swap nginx certbot | `NGINX_SOURCE=stable`, `FW_WEB=yes` |
| `docker` | minimal + sysctl limits swap docker | `FW_DOCKER_PROTECT=yes` |
| `full` | web + docker + git + wg-network | `NGINX_SOURCE=stable`, `FW_WEB=yes`, `FW_DOCKER_PROTECT=yes` |

Свой профиль — файл `/etc/ubuntu-bootstrap/profiles.d/<имя>.conf` того же формата; первая строка-комментарий становится его описанием в `profiles` и мастере. Имя: строчные буквы, цифры и дефис, до 32 символов. Пользовательский профиль с тем же именем, что встроенный, имеет приоритет.

## Сценарии

### Чистый сервер, интерактивно

```bash
curl -fsSL https://raw.githubusercontent.com/Ange1oc/devops_template/main/ubuntu/bootstrap/install.sh | sudo bash -s -- --run
```

Мастер предложит профиль `minimal`, пользователя `deploy`, скопирует ему ключи root (если других нет), запретит вход по паролю, запретит вход root (если у администратора есть ключ и рабочий sudo), включит UFW и fail2ban, автообновления и постоянный журнал. При смене порта или включении UFW — проверка доступа из новой сессии.

### Неинтерактивно

```bash
sudo ubuntu-bootstrap apply --profile minimal \
    --set ADMIN_USER=deploy --set 'ADMIN_SSH_KEYS=ssh-ed25519 AAAA... admin' \
    --set ADMIN_SUDO_MODE=nopasswd --yes
```

`--yes` отвечает «да» на подтверждения опасных действий (NOPASSWD, включение UFW, удаление конфликтующих пакетов Docker) и подставляет умолчания. Предохранители не снимаются: если у `deploy` нет ключа, запрет паролей не произойдёт, команда вернёт 3 и ничего не изменит.

Подтверждение доступа без терминала (`SSH_CONFIRM=auto`, умолчание) выполняется самопроверкой на сервере: sshd отвечает на новом порту и порт разрешён в UFW. Если между вами и сервером есть фильтр провайдера (security group), самопроверка его не увидит — используй `SSH_CONFIRM=wait` и `confirm` из новой сессии.

### Файл конфигурации в репозитории

```bash
sudo ubuntu-bootstrap --config ./servers/web01.conf plan
sudo ubuntu-bootstrap --config ./servers/web01.conf apply --yes
```

Пример файла — [examples/web.conf](../../examples/web.conf). Секреты (например `ADMIN_PASSWORD_HASH`) лучше держать в файле с правами 600, а не передавать через `--set`: аргументы командной строки видны в `ps`.

### cloud-init

```yaml
#cloud-config
runcmd:
  - curl -fsSL https://raw.githubusercontent.com/Ange1oc/devops_template/main/ubuntu/bootstrap/install.sh | bash -s -- --ref main
  - >
    ubuntu-bootstrap apply --profile minimal
    --set ADMIN_USER=deploy
    --set 'ADMIN_SSH_KEYS=ssh-ed25519 AAAA... admin@laptop'
    --set ADMIN_SUDO_MODE=nopasswd
    --set SSH_CONFIRM=auto
    --yes
```

При первой загрузке нет SSH-сессии, поэтому UFW включается без ожидания подтверждения, а sshd подтверждается самопроверкой. Полный пример: [examples/cloud-init.yaml](../../examples/cloud-init.yaml).

### Ansible / CI со сменой порта

Используй `SSH_CONFIRM=wait`: процесс не блокируется, таймер взводится, playbook переподключается по новому порту и выполняет `confirm`:

```yaml
- command: >
    ubuntu-bootstrap apply --profile minimal --set ADMIN_USER=deploy
    --set 'ADMIN_SSH_KEYS={{ admin_pubkey }}' --set ADMIN_SUDO_MODE=nopasswd
    --set SSH_PORT=2222 --set SSH_CONFIRM=wait --set SSH_CONFIRM_TIMEOUT=300 --yes
  register: apply
  failed_when: apply.rc not in [0, 4]
- set_fact: { ansible_port: 2222 }
- command: ubuntu-bootstrap confirm
```

Если переподключение не удалось, через 300 секунд порт вернётся обратно, а старый порт всё это время остаётся открытым в UFW. Полный пример: [examples/ansible.yml](../../examples/ansible.yml).

### Изменение настроек после применения

```bash
sudo ubuntu-bootstrap config set SSH_PORT=2222 F2B_MAXRETRY=3
sudo ubuntu-bootstrap plan
sudo ubuntu-bootstrap apply
```

Переприменяются только модули, чьи опции изменились или чьё состояние больше не соответствует желаемому. `apply --reapply` выполняет все выбранные модули заново (идемпотентно: файлы с тем же содержимым не перезаписываются).

### Смена SSH-порта: что происходит

1. Предохранители: новый порт не занят; у разрешённых пользователей есть ключи.
2. Если UFW активен, новый порт открывается в нём **до** перезапуска sshd (тем же действием, что и у модуля firewall: `limit` или `allow`).
3. Записывается `/etc/ssh/sshd_config.d/00-ubuntu-bootstrap.conf`, проверяется `sshd -t`, sshd перезапускается (на Ubuntu 22.10+ — `ssh.socket`, иначе порт не изменится). Текущая сессия переживает перезапуск.
4. Взводится таймер отката (`SSH_CONFIRM_TIMEOUT`, 180 с). Интерактивно: обратный отсчёт и вопрос «вход в новой сессии успешен?». `auto` без терминала: самопроверка. `wait`: процесс завершается, ожидание продолжается.
5. После подтверждения (`y`, самопроверка или `confirm`) старый порт закрывается в UFW — но только правила с пометкой `SSH (ubuntu-bootstrap)`; чужие правила не трогаются, о них выводится предупреждение.
6. Без подтверждения — откат: прежний конфиг, перезапуск sshd, удаление нового порта из UFW. Перезагрузка в этом окне обрабатывается recover-сервисом.

## Логи и история

| Что | Где |
|---|---|
| Полный лог запуска (все команды, их вывод, ответы на вопросы, записанные файлы) | `/var/log/ubuntu-bootstrap/<RUN_ID>.log` (права 600) |
| События (старт, завершение, откат, подтверждение) | `journalctl -t ubuntu-bootstrap` |
| Журнал изменений и бэкапы | `ubuntu-bootstrap history <RUN_ID>` |
| Состояние модулей | `/var/lib/ubuntu-bootstrap/modules/<модуль>.env` |

Секреты не попадают в лог: пароли задаются через `passwd` с терминала или хэшем, diff в dry-run маскирует строки с `PASSWORD`, `TOKEN`, `SECRET`, `PrivateKey`.

## Автодополнение

`install.sh` подключает `/etc/bash_completion.d/ubuntu-bootstrap`: дополняются команды, подкоманды `config`, модули для `--only/--skip`, профили для `--profile`, имена опций для `--set`, идентификаторы запусков для `rollback` и `history`. Действует после нового входа в shell.
