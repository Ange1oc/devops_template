# Аудит

Независимая проверка результата: ubuntu-bootstrap (самоаудит после реализации, прогона тестов и второго прохода по коду) и wg-network (`ubuntu/wg`, чтение кода без изменений — каталог живёт в основном чекауте и правится отдельно; правки предлагаются списком).

## ubuntu-bootstrap

### Исправлено в первой итерации (реализация и тесты)

| Находка | Где | Исправление |
|---|---|---|
| Исходный скрипт сверял отпечаток ключа nginx.org с **первым** ключом файла, а файл содержит три ключа → установка nginx.org всегда падала | `apt_repo_add` | проверяется вхождение официального отпечатка в список всех ключей файла |
| Смена порта на Ubuntu 22.10+ через `systemctl reload ssh` не действует (socket-активация, LP#2069041) | `sshd_apply` | `daemon-reload` + `restart ssh.socket`, проверка `ss` после |
| `exec 3<>/dev/tcp/… 2>/dev/null` делал перенаправление stderr постоянным — вывод после самопроверки терялся | `ssh_selfcheck` | `{ exec 3<>…; } 2>/dev/null` |
| `systemctl reload fail2ban` сразу после `enable --now` попадал в момент старта и падал | `modules/fail2ban.sh` | reload только для уже работавшего сервиса; ожидание готовности jail |
| recover-юнит с `Before=ssh.socket` вызывал `restart ssh.socket` → цикл задач systemd, загрузка зависала | `systemd/…recover.service` | без ordering-зависимости от sshd, `WantedBy=multi-user.target`, `TimeoutStartSec=300` |
| `render \| file_write` выполнялось в подоболочке: `FILE_CHANGED` терялся, модули не перечитывали сервисы | точка входа | `shopt -s lastpipe` |
| `sshd -T` падает без `/run/sshd` (socket-активация до первого подключения) | `sshd_ready` | каталог создаётся перед вызовом |
| Удаление старого SSH-порта из UFW: правило `LIMIT`, а не `ALLOW`; `ufw delete` несуществующего правила возвращает 0 | `modules/ssh.sh` | действие берётся из `ufw status` |
| `plan` на чистом сервере отказывался закрывать пароли: пользователь ещё не создан | `plan_mark`, `human_users` | «планируемые факты» dry-run |
| `is_duration` не принимал `1month` (journald) → `config init` создавал невалидный конфиг | `lib/validate.sh` | расширен список единиц; unit-тест на валидность всех профилей |
| Аудит считал `!` в `/etc/shadow` «пустым паролем» | `commands/audit.sh` | только действительно пустое поле |
| SIGHUP при обрыве SSH убивал `apt-get` на полпути | `run` | дети игнорируют HUP, bash обрабатывает сигнал между командами и уводит вывод в лог |
| В режиме `SSH_CONFIRM=wait` старый порт закрывался в UFW до подтверждения — окно без доступа при неработающем новом порте | `modules/ssh.sh` | старый порт закрывается только после подтверждения (`mod_confirmed`), правила SSH помечены комментарием |
| `ufw` перезаписывает свои файлы в ASCII: не-ASCII комментарии в блоке `after.rules` ломали `ufw default` | `fw_docker_block` | комментарии только латиницей |
| fail2ban на 22.04: `python3-systemd` только Recommends, jail с `backend=systemd` не стартовал | `modules/fail2ban.sh` | пакет ставится явно |
| Docker-in-Docker в тестах: overlay поверх overlay не монтируется | `tests/e2e.sh` | `/var/lib/docker` и `/var/lib/containerd` — отдельные volume |

### Остающиеся риски и допущения

- `SSH_CONFIRM=auto` без терминала подтверждает по локальной самопроверке (баннер sshd на новом порту, порт разрешён в UFW). Фильтры провайдера (security groups) она не видит — для них `SSH_CONFIRM=wait` + `confirm` из новой сессии.
- `--set ADMIN_PASSWORD_HASH=…` виден в `ps` на время команды; для секретов предпочтительнее файл конфигурации (600, root).
- Откат не удаляет пакеты и не отменяет `apt upgrade`; `rollback RUN_ID` восстанавливает конфигурацию и перечитывает сервисы.
- Сигналы TERM/HUP обрабатываются между шагами: текущая команда доводится до конца, затем запуск помечается `interrupted`; dpkg никогда не прерывается на полпути.
- Ключи `ADMIN_SSH_KEYS_GITHUB` доверяются GitHub + TLS; `git`-модуль берёт host keys GitHub из `api.github.com/meta`, для остальных хостов — `ssh-keyscan` с показом отпечатков.
- `--force` снимает предохранители целиком. Это осознанный выбор администратора; таймер отката и подтверждения остаются.
- В контейнерах пропускаются swap, NTP-демон, snap; sysctl применяется «на лету» только для доступных ключей.
- Релизные подписи проверяются только при заданном `UBB_SIGNING_KEY_FPR` (ключ получается с keys.openpgp.org); без него доверие — TLS + SHA256SUMS релиза, как у get.docker.com.
- `public_ip` для DNS-проверки certbot обращается к `api.ipify.org`; при недоступности используется IP интерфейса по умолчанию, что за NAT даст ложный отказ (`CERTBOT_DNS_CHECK=no`).

## wg-network (`ubuntu/wg`, v2.0.0)

Каталог `ubuntu/wg` меняется параллельно, поэтому находки сверены с состоянием файлов на момент завершения работы.

Общая оценка: архитектура продуманная — транзакции со снимками, предохранители для SSH-маршрутов, dead-man таймер вне сессии, защита от перезагрузки через drop-in `ExecStartPre`, валидация всего ввода, атомарная запись с правами 600, проверка доверенности каталога программы. Ниже — что стоит поправить.

| # | Серьёзность | Находка | Рекомендация |
|---|---|---|---|
| 1 | средняя | `install.sh` скачивает `api.github.com/repos/…/tarball/REF`: лимит 60 запросов/час на IP без токена (NAT офиса/CI упирается), нет способа закрепить содержимое кроме `--ref <sha>`, нет проверки контрольных сумм релиза | использовать `github.com/<repo>/archive/<ref>.tar.gz` без токена (не лимитируется как API), добавить `--sha256` и релизные `SHA256SUMS`, как в `ubuntu/bootstrap/install.sh` |
| 2 | низкая | `fetch_remote`: `curl` без `--max-time` — зависший TLS-поток блокирует установку бесконечно | `--max-time 120` (у `wget` есть `--timeout`, но он на чтение, не на всю операцию) |
| 3 | низкая | `sys_install_wireguard` вызывает `apt-get` без ожидания блокировки dpkg: сразу после загрузки сервера unattended-upgrades держит lock и `init-peer` падает | подождать освобождения `/var/lib/dpkg/lock-frontend` (см. `apt_wait` в bootstrap) |
| 4 | низкая | `kv_load` принимает любой ключ до `=` (в т.ч. с пробелами); `st_validate` проверяет значения, но не имена ключей — повреждённый `node.env` с ключом `ROLE =hub` молча даст пустой `ROLE` и сообщение «ROLE должен быть hub или peer» без указания на причину | проверять имя ключа регуляркой `^[A-Z][A-Z0-9_]*$` и сообщать строку |
| 5 | низкая | Токен `invite` содержит PSK и печатается в stdout; README советует вставлять по запросу — хорошо, но `invite` не предупреждает, что токен одноразовый по смыслу и его нельзя пересылать в открытых каналах | добавить предупреждение в вывод `invite` и срок жизни резервации (`PENDING` без TTL остаётся навсегда) |
| 6 | низкая | `deadman_wait` при `--yes` и `GUARD_LEVEL=0` подтверждает автоматически сразу после `apply_postcheck` — для `restart` без затронутой SSH-сессии это нормально, но стоит явно логировать, какие проверки пройдены (адрес, порт, peer в ядре) | дополнить сообщение перечнем проверок |
| 7 | инфо | `tests/run.sh e2e` требует непривилегированных user namespaces; на хостах с `kernel.unprivileged_userns_clone=0` или AppArmor-ограничением (Ubuntu 24.04 по умолчанию ограничивает userns для неподписанных профилей) тесты молча пропускают сетевую часть | документировать `sudo tests/run.sh e2e` как fallback |
| 8 | инфо | Два инструмента дублируют инфраструктуру (core/validate/ip, тестовый фреймворк). Это осознанная независимость; при росте стоит вынести общий `ubuntu/lib` | решение на усмотрение сопровождающего |

Интеграция с bootstrap: модуль `wg-network` только устанавливает инструмент (`ubuntu/wg/install.sh` того же репозитория и ref), сеть настраивается `wg-network` отдельно; `sysctl`-модуль не отключает `ip_forward`, если установлен WireGuard; `firewall`-модуль не трогает UDP-порты WireGuard (их открывает сам `wg-network init-hub`).
